# Style and Grace

Style and Grace is a GitHub Pages blog with no handwritten JavaScript. The work
is split three ways, all in C:

- **Build time (native C)**: `tools/generate_static.c` links the render
  kernels from `blog/wasm` natively and bakes post bodies, comments, the home
  card, section accents and the relations graph (SVG) into static HTML.
- **CWIST WASI 0.2 component**: the search kernel (`blog/wasm`) is a CWIST app
  built for `wasm32-wasip2` that exports CWIST's `cwist-guest` WIT world
  (`lib/cwist/wit/cwist.wit`).
- **Emscripten page host (C)**: WASI 0.2 has no DOM, events or storage, so
  `blog/ui/blog_ui.c`, built with Emscripten into `assets/blog-ui.{js,wasm}`,
  owns that side: theme toggle, search UI, loading the component, and
  serializing/parsing the HTTP/1.1 messages exchanged with it.

## Architecture

### Build pipeline

`make wasm-blog` (WASI 0.2 component):

1. **wasi-sdk clang** links `blog/wasm/{blog_guest,search,search_ui}.c` against `libcwist_wasip2` as a reactor core module
2. **wit-bindgen** generates the canonical-ABI bindings for the `cwist-guest` world
3. **wasm-tools component embed** produces the WASI 0.2 component (`blog.component.wasm`)
4. **jco transpile** (`--no-nodejs-compat --tla-compat`) emits a browser ES module plus core wasm shards
5. **esbuild** bundles the jco output and the preview2-shim browser build into `assets/cwist-blog.mjs`

`make ui-blog` (Emscripten): `blog/ui/blog_ui.c` -> `assets/blog-ui.js` + `assets/blog-ui.wasm`

`make static-site` (native): `bin/bloggen` writes `docs/`, including comments from `data/comments.json` when present

### Runtime path

1. Every page loads `assets/blog-ui.js` in `<head>`; its C `main()` applies the
   saved theme (`cwist-theme` in `localStorage`) or `prefers-color-scheme`.
2. On the search page the same module imports `cwist-blog.mjs`, pushes
   `search-index.json` into the component, and handles input debounce and
   arrow-key navigation.
3. On post pages it runs highlight.js over code blocks and loads MathJax when
   the body carries `data-math`.

| Route | Request body | Response | Caller |
|---|---|---|---|
| `PUT /search/index` | `search-index.json` | 204 | `blog_ui.c` |
| `POST /search` | query | result-card HTML | `blog_ui.c` |

Browser API calls live only in the `EM_JS` bindings inside `blog_ui.c` (one
API call per binding). Every `.js`/`.mjs` that ships is generated by
Emscripten, jco or esbuild.

Commenting is a plain GET form that opens a prefilled GitHub issue. Stored
comments come from `data/comments.json` and appear on the next deploy.

## Directory / component guide

- `tools/generate_static.c` — page shell / body / comments / relations / navigation generator (native C)
- `blog/wasm/blog_guest.c` — CWIST app routes and the `cwist-guest` exports
- `blog/wasm/*.c` — markdown / comment / search / relations kernels, shared by the generator and the component
- `blog/ui/blog_ui.c` — Emscripten page host
- `blog/package.json` — pins jco, preview2-shim, esbuild
- `posts/<category>/*.md` — post sources
- `data/comments.json` — comments, keyed `<category>/<slug>`
- `docs/` — generated GitHub Pages output

## Development and build notes

Initialize only the submodules the build needs:

```bash
git submodule update --init lib/md4c lib/cwist
git -C lib/cwist submodule update --init --filter=blob:none lib/cjson lib/libttak lib/boringssl
```

Toolchain: wasi-sdk 25, wasm-tools 1.259, wit-bindgen 0.62 (same pins as `lib/cwist` CI), Emscripten 5.0.0, Node 22.

```bash
make wasm-blog WASI_SDK=$HOME/toolchains/wasi-sdk-25.0-x86_64-linux   # component + bundle
make ui-blog                                                          # page host
make clean static-site                                                # generate docs/
# or all of it: make site WASI_SDK=...
```

Point `WASM_TOOLS=` / `WIT_BINDGEN=` / `EMCC=` at the binaries if they are not on PATH.

## Current status and known limitations

- The `cwist-guest` world has a single synchronous `dispatch`, so jco-lowered export calls run on the main thread.
- Category listing pages still use pre-rendered HTML snippets.
- The theme is applied once the page-host wasm is ready, so a saved theme that
  differs from the OS preference can briefly show the other theme on first paint.
- The static generator keeps full post sources in memory while building.
